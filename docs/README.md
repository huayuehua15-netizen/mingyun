# 命云 MingYun · 开发文档总索引

> 一个可 Docker 一键自部署、代码完全开源的 AI 术数排盘与解读平台。已支持**六爻、大六壬、紫微斗数**三种起盘方式，内置 OpenAI 兼容模型网关，可接 DeepSeek / 通义千问 / 智谱 GLM / Kimi / Ollama 本地模型。
>
> 目标技术栈：**Vue 3 + TypeScript / Go 1.25 / PostgreSQL / Redis / Docker Compose**。当前仓库先落单二进制 + 内存存储，Postgres/Redis 与账号体系在 M2。

「命云」为暂定代号，仓库名建议 `mingyun`，正式名在 v1.0 发布前确定即可，不影响工程结构。

## 五条不可动摇的设计决策

这五条决定了后面所有文档的写法，改动任何一条都会引发大面积返工，先在此立住。

1. **排盘引擎是独立的 Go module，与 Web 框架完全解耦。**
   `paipan` 自带 `go.mod`，不依赖 Gin、不碰数据库、不发网络请求、不启 goroutine。给定相同输入必得相同输出。这样它能单独测试、被别人 `go get`、被任意语言的服务调用（备有 HTTP 与 CLI 两种包装）。

2. **盘面一旦生成即冻结为快照，永不重算。**
   每张盘存 `chart_snapshot`（JSONB）+ `engine_version` + `calendar_version`。三年后规则改了，老盘仍按老版本呈现，AI 解读也基于当时的快照。术数工具最忌讳"同一卦两次排出来不一样"。

3. **AI 只解释盘面，绝不参与排盘。**
   模型拿到的是引擎输出的**扁平事实清单（facts）**，不是原始 JSON，也不允许自行推演干支、纳甲、星曜位置。所有"事实"必须可追溯到盘面字段。

4. **模型层只依赖 OpenAI 兼容协议。**
   一套 `base_url + api_key + model` 配置即可切换任意国内外模型（含 Ollama、vLLM、SGLang 本地推理）。不做各家 SDK 的深度绑定。

5. **单机 Docker Compose 起步，不引入 K8s。**
   目标用户是"自己有台服务器或 NAS 的人"。五个容器能跑起来，就是产品的完成态。集群化是使用者自己的选择，不是项目的默认成本。

## 名词约定

| 名词 | 含义 |
|---|---|
| 起盘 / 排盘 | 由时间、出生信息等输入推算出完整术数盘面的过程 |
| 盘面 / chart | 排盘引擎输出的结构化结果，含全部爻、星、宫、课 |
| facts | 盘面的扁平事实清单，供 AI 使用，也是前端高亮的索引 |
| 解读 / reading | AI 基于盘面生成的断语文本 |
| 术数 / method | 六爻（liuyao）、大六壬（daliuren）、紫微斗数（ziwei） |
| 引擎版本 | 每个术数独立发版，如 `liuyao@1.0.0` |
| 主体（subject） | 配额计量的对象，可以是注册用户或游客设备 |
