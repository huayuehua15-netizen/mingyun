# 07 · 前端设计规范

## 1. 设计基调

这个站点的视觉要回答一个问题：**怎么让"算命"看起来不像骗子，又不像寺庙。**

答案是：**做成一本古籍工具书的样子**。宣纸底、墨色字、朱砂点睛、细线分隔、大量留白。不要发光、不要渐变、不要拟物质感、不要"科技玄学"的紫蓝配色——那三种正是廉价算命 App 的视觉特征。

具体约束：

| 允许 | 禁止 |
|---|---|
| 平涂色块、单色细线、纸纹底纹（低透明度噪点） | 线性/径向渐变、玻璃拟态、发光、投影特效 |
| 宋体标题 + 黑体正文 | 书法字体做正文、圆体、手写体 |
| 1px 墨线分隔、方格与表格式排布 | 卡片圆角 + 大阴影的"卡片流" |
| 克制动效（≤ 400ms，缓动为 ease-out） | 弹跳动效、粒子、飘落花瓣 |

## 2. 色彩

| 名称 | 色值 | 用途 |
|---|---|---|
| 宣纸 | #F4EFE6 | 页面底色 |
| 素纸 | #FBF8F1 | 卡片/盘面底 |
| 墨 | #1B1A18 | 主文字、爻线 |
| 淡墨 | #5C574E | 次要文字 |
| 界线 | #D8D0C0 | 分隔线、网格 |
| 朱砂 | #A63A2B | 强调、动爻、忌、主星 |
| 石青 | #37576B | 吉、次强调、链接 |
| 藤黄 | #C9A063 | 土、中性标记、装饰线 |
| 冷灰 | #8C857A | 禁用、已删除 |

原则：**吉凶不靠颜色单独区分**（色盲友好），一律配符号或文字：动爻加 ○/×，吉加"吉"字标记，忌加"忌"字标记。颜色只是强化。

## 3. 字体与排版

| 层级 | 字体 | 字号/行高 |
|---|---|---|
| 页面标题 | Noto Serif SC 600 | 32/44 |
| 区块标题 | Noto Serif SC 600 | 20/30 |
| 正文 | Noto Sans SC 400 | 15/26 |
| 干支、数字、卦符 | 思源宋体 + `font-variant-numeric: tabular-nums` | 与正文同 |
| 注释 | Noto Sans SC 400 | 13/22 |

字重只用 400 与 600 两档，避免视觉噪音。中文段落 `letter-spacing: 0.02em`。

网格：8pt 基准。间距取值 4/8/12/16/24/32/48/64。桌面版内容最大宽度 1200px，结果页左盘面 720px、右解读 440px。

## 5. 六术盘面渲染方案

六种盘形态差异太大，不能强行统一组件，但可以统一"容器契约"：接收 `payload` + `highlightAnchor` + `onAnchorClick`，输出可导出的 DOM。

### 5.1 六爻：SVG

- 每爻一个 `<g>`，含爻线（阳为整线、阴为断线）、爻位序号、纳甲、六亲、六神、世应标记、动爻标记（○/×）、伏神（爻线下方小字）。
- 用 SVG 而非 Canvas：爻线要可点击、要能被 CSS 高亮、要能无障碍标注。
- 变卦并列右侧，两卦之间用细线连接动爻。
- 高亮：给对应 `<g>` 加 `.is-cited` 类，描边转为朱砂，0.3s 过渡。

### 5.2 大六壬：CSS Grid 4×4 天地盘

- 外围 12 宫围成 4×4 环，中心 2×2 放课体、三传与月将/占时摘要。每宫同时排地盘支、天盘支、天将、六亲与神煞角标。
- 当前实现用 DOM 而非 Canvas：十二宫需要文字可选中、可被读屏，且移动端要能横向滑动查看，DOM 的国际化与缩放成本更低。
- 四课与三传在盘下用表格再列一遍，避免只靠盘面小字读取；天地盘与表格共用同一份 payload，不做二次推导。
- 交互预留：点击宫位或三传项时传 `onAnchorClick`，用于后续 facts 高亮；当前先保证可读与可翻回原盘。

### 5.3 紫微：CSS Grid

- 4×4 网格：外围 12 宫（每宫含宫名、地支、主星、辅星、四化标记、大限岁数），中间 2×2 为基本信息区（命主、身主、五行局、生年四化）。
- 用 DOM 不用 Canvas：紫微盘文字密度最高，且需要文本可选中、可复制、可被读屏。
- 四化用角标（禄/权/科/忌 四色小字），不用彩色圆点。

### 5.4 小六壬：路径 + 3×2 宫格

- 上方一条“月 → 日 → 时”三宫路径，用箭头连接；落宫以朱砂描边强调。
- 下方 3×2 六宫格，每格显示宫名、五行·天将·方位、一句取象与吉/凶小签；落宫格加朱砂内描边。
- 只用 DOM，三宫与六宫同源于 payload，不在前端重算落宫。

### 5.5 梅花：本卦 / 互卦 / 变卦三列

- 三列六爻图，自下而上编号；本卦动爻用朱砂横线并标“动”。
- 每列下方标上卦、下卦；盘下用一条体用关系条呈现“体 / 用”与生克方向。
- 变卦关系单独显示（如“变生体”），不与体用关系混写。

### 5.6 奇门：传统九宫 3×3

- 方位固定：上排巽四、离九、坤二；中排震三、中五、兑七；下排艮八、坎一、乾六。
- 每宫显示宫名、方位、天盘干 / 地盘干、九星、八门、八神，以及空、马、迫、符、使角标；中五宫只显示天禽与天地盘干。
- 值符与值使落宫用朱砂/墨色双描边区分；盘下给四柱与近事用神（考试景门/天辅，比赛值符/时干/伤门/天冲）落宫。
- 窄屏保留横向滚动，不压缩九宫文字；快捷键与点击暂不接入 facts 高亮。

## 6. 摇卦交互

这是全站唯一的"表演时刻"，要做得有分量，但不能浮夸。

流程：点"开始摇卦" → 三枚铜钱并排出现 → 每次"摇"触发一次 600ms 动效 → 落定后显示背数 → 该爻从下往上写入卦盘 → 六次结束 → 盘面整体淡入。

**铜钱翻面用纯 2D 实现**：`transform: scaleY()` 从 1 压到 0（币面消失）后切换正反面纹理，再从 0 展开到 1。全程无 `perspective`、无 3D 旋转、无光影——这是刻意规避"廉价 3D 感"。铜钱用两枚 SVG 纹样（字面/背面），线条单色。

节奏控制：

| 阶段 | 时长 | 备注 |
|---|---|---|
| 单击"摇" | — | 也支持键盘 Space |
| 抛起 | 200ms | `translateY -24px` + `scaleY 0.2` |
| 落定 | 300ms | 回弹一次，不弹多次 |
| 结果呈现 | 100ms | 背数文字淡入 |
| 爻线写入 | 200ms | 自下而上 |

**防作弊感设计**：结果下方显示"本次摇卦记录"入口，点开可见六组背数与校验码。这不是给普通用户看的，是给质疑者看的。

## 7. 解读面板

- 结构：问题 → 四段小节（盘面要点/断语/应期/建议） → 免责声明。
- 流式渲染：`fetch` + `ReadableStream` 手写 SSE 解析（EventSource 不支持 POST 与自定义头），封装成 `useReadingStream()`。
- **按帧批处理**：每收到一个 delta 不直接改 DOM，先入缓冲，`requestAnimationFrame` 每帧统一 flush，否则长文本流会让主线程抖动。
- 引用交互：断语里带锚点标记的句子，鼠标悬停时右侧盘面同步高亮；点击则滚动到对应爻/宫并短暂描边。
- 骨架屏：首 token 未到时显示三条灰线 + "正在推演…"，不显示百分比。

## 8. 状态与数据层

| 层 | 方案 | 职责 |
|---|---|---|
| 服务端状态 | @tanstack/vue-query | 列表、详情、额度，自动缓存与失效 |
| 全局 UI 状态 | Pinia（auth / ui / reading） | 登录态、主题、当前会话 |
| 类型 | openapi-typescript 生成 | 与 05 文档的 OpenAPI 契约同源 |
| 表单 | vee-validate + zod | 出生信息、日期、时区的复杂校验 |

规则：**组件不直接发请求**，一律通过 `api/` 层函数；`api/` 层的入参出参类型全部来自生成文件，手写类型视为违规。

## 9. 性能

| 项 | 目标 | 手段 |
|---|---|---|
| 首屏 JS | < 180KB gzip | 路由懒加载；盘面组件按 method 动态 import；Naive UI 按需引入 |
| 首屏 LCP | < 1.8s | 字体 `font-display: swap` + 预加载首屏字重；纸纹底图用 CSS 生成的噪点而非大图 |
| 盘面渲染 | < 16ms/帧 | 大六壬 Canvas 分层（底图静态层 + 交互层），避免整盘重绘 |
| 流式文本 | 60fps | rAF 批处理 + `content-visibility: auto` |

## 10. 适配与无障碍

- 断点：≥1280 三栏、1024–1280 两栏、768–1024 单栏 + 抽屉、<768 移动布局。
- 盘面在窄屏可横向滚动并支持双指缩放（`touch-action: pinch-zoom`）。
- 所有交互元素可键盘操作；摇卦支持 Space/Enter；盘面焦点环用朱砂 1px。
- 爻与宫位的 `aria-label` 用完整语义（"三爻，阳，妻财酉金，发动"），不读符号。
- 对比度：正文对底色 ≥ 7:1，次要文字 ≥ 4.5:1。

## 11. 导出与分享图

- 前端用 `html-to-image` 对盘面容器截图，2 倍像素比输出；**字体必须内嵌为 base64**，否则分享图在别人设备上掉字。
- 分享图版式：竖版 1080×1440，顶部项目 Logo 与卦名，中部盘面，底部一句摘要 + 二维码。
- 服务端不引入 headless 浏览器（`chromedp` 会让镜像膨胀数百 MB），v1 全部前端生成，上传到 `/charts/{id}/share` 存对象存储。

## 12. 工程规范

- TypeScript `strict: true`，禁用 `any`（lint 规则 `@typescript-eslint/no-explicit-any` 报错）。
- 组件命名：盘面类 `LiuYaoBoard` / `DaLiuRenBoard` / `ZiWeiBoard` / `XiaoLiuRenBoard` / `MeiHuaBoard` / `QiMenBoard`；通用 `BoardShell`。
- 样式：CSS 变量定义色板与间距，禁止散落魔法值；不引入 Tailwind（与 Naive UI 主题体系冲突）。
- 目录：`views/` 页面、`components/board/` 盘面、`components/reading/` 解读、`api/` 请求、`stores/` 状态、`styles/` 主题。
- 提交前必跑：`pnpm typecheck`、`pnpm lint`、`pnpm test`（组件测试用 Vitest + Testing Library）。
